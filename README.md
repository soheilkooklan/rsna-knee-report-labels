# RSNA 2026 knee MRI: report labels, an image teacher and the gap to expert labels

Code and data for the report "Report-Derived Labels, an Image Teacher and the Gap to Expert Labels in Knee MRI: An Analysis of One Entry to the RSNA 2026 Knee Abnormality Detection Challenge" by Soheil Kooklan.

The models here are research code for a Kaggle challenge. They are not meant or validated for clinical use.

Release v1.0 is the version described in the arXiv paper.

## Layout

    rsna_knee/            package used by the Kaggle notebooks
      targets.py          training targets: report labels mixed with an image teacher
      cache3.py           image cache, 6 series slots x 16 slices x 256 px, 140 mm
      model2.py           3-slice windows, ResNet50, gated attention per slot, slot attention per finding
      train2.py           training loop; defaults are the reported run (family r50v3)
      infer2.py           checkpoint discovery, family checks, blending at test time
      rank_tools.py       percentile ranks, co-occurrence weights, explaining-away correction
      report_labels.py, dicom_io.py, data.py, model.py, train.py, infer.py   first entry
      ntejas_arms.py      inference for the public NTejas-1 checkpoints
    notebooks/            generated by tools/make_notebooks_v2.py
      04_train_v2         one fold per run on two T4 GPUs
      05_submit_v2        rebuilds the test cache from the hidden DICOM and writes submission.csv
      06_build_cache_v3   builds the training cache on CPU in three shards
      07_slice_audit      CPU, headers only: slice order against the stack normal, spacing, tilt
      08_slot_attention   GPU: mean finding-to-slot attention and the learned slot prior per fold
    tools/
      reproduce_tables.py every number of the paper -> results/numbers.json, results/tables.md
      make_figures.py     figures of the paper -> results/fig_*.pdf
      make_fold_manifest.py
      common.py           loaders, AUC, bootstrap intervals (1,000 resamples, seed 0), paired permutation
                          test, paired DeLong-type test, Holm
      kaggle_cells/       cells added to public notebooks (explaining away, blending, header probe)
    tests/
      test_units.py       229 cases (200 of them random slice orientations): slice order, target
                          fallbacks, rank correction, file and checkpoint discovery (packed and
                          unpacked checkpoints in either order), cache copies, file alignment,
                          the DeLong-type test
      smoke_kaggle.py     CPU end-to-end run of notebooks 04 and 05 on synthetic DICOM, inside a
                          new temporary folder; it never touches the real /kaggle
    data/
      labels_v1_opus45.csv, teacher_oof_armA.csv   from NTejas-1 (MIT, LICENSE_NTejas_MIT.txt)
      oof_v2_r50v3_all.csv   our five-fold out-of-fold predictions
      fold_manifest.csv      fold and gold flag of every training study
      meta_train.csv         one DICOM header per training study (no age, no dates)
      submissions.csv        every scored submission with public and private score
      learning_curves.csv    per-epoch validation AUC of the reported folds, from the Kaggle logs
      slice_audit.csv        header audit of all 24,371 training series (notebook 07)
      private_scores.csv     number of teams per private leaderboard score (no team names)
      runs/                  out-of-fold predictions, histories and checkpoint hashes of the later runs
                             (labels-only student, fold-0 ablations), slot attention (notebook 08)
      logs/                  Kaggle logs of the later runs and of reported fold 2; smoke_cpu.log is a
                             clean run of tests/smoke_kaggle.py

## Reproducing the paper

    pip install -r requirements.txt
    make test       # unit tests, no DICOM, no GPU
    make tables     # results/numbers.json and results/tables.md
    make figures    # results/fig_*.pdf
    make smoke      # end-to-end CPU run on synthetic DICOM in a temporary folder (about 9 min)

Everything in the results section of the paper comes from `make tables` and the files in `data/`. This reproduces the analyses from frozen out-of-fold predictions; it does not retrain the model and cannot check the hidden leaderboard, whose scores are recorded in `data/submissions.csv` as Kaggle showed them. Training needs the competition data on Kaggle: run notebook 06 (three CPU shards), then notebook 04 once per fold with `FOLD` set to 0 to 4, then notebook 05 with the five checkpoints attached. One fold takes about 68 minutes. On some Kaggle sessions, reading the mounted cache at random positions slowed a training step from 0.22 s to about 20 s; with `LOCAL_COPY = True` (the default) notebook 04 first copies the 27.7 GB cache to the local disk, which took about 8 minutes, and logs a read-speed check. Each copied shard gets a record of the source size, time and SHA-256; a local copy is reused only when it still matches that record, and an interrupted copy is never left under the final name. The notebooks are written by `make notebooks`, and their defaults are the reported run: `ENCODER = "rad_resnet50"`, `TAG = "r50v3"`, `CACHE = "v3"`, `CROP = True` (224 px of 256), `SLOT_PRIOR = True`, `SEED = 2026`. The released `oof_v2_r50v3_all.csv` comes from checkpoints trained by notebook 04 with these settings. Each checkpoint stores its configuration and the order of the findings, and each training run of the current notebook writes `run_<tag>_f<folds>.json` with the settings, package versions and the SHA-256 of every checkpoint and input file. The runs in `data/runs/` were made with the notebook cells of the earlier version, which did not write these files; for them `data/runs/manifest.csv` records settings and checkpoint hashes and the logs record the run, but no package versions. Notebook 05 compares every copy of a checkpoint name by content, whether the copy is a .pt file or the folder an archive tool unpacked it into, and refuses different contents under one name; it refuses a family whose folds disagree on encoder, cache, input size, window size, slot prior, target scheme, inference windows or finding order, an empty family, and (with `REQUIRE_FOLDS = 5`) a family with a missing fold; it writes no fallback file unless `ALLOW_BENCHMARK = True`, so a crash or timeout cannot leave a constant submission behind. The reported folds were trained before the data sampler was seeded, so a rerun gives close but not identical weights.

## What this release reproduces

The release is analysis-reproducible: every table and figure of the paper is recomputed from the frozen predictions in `data/`. It is not end-to-end leaderboard-reproducible: the hidden test labels are not available, the trained checkpoints are not included, and the public ensemble behind the 0.943 private score belongs to its authors.

## How the 0.943 private score was made

The submission that set the final rank is the newer version of the public notebook RSNA_Versia_7 by evgendvorkin, run unchanged, with `tools/kaggle_cells/explaining_away_cell.py` added as its last cell (`LAM = -0.1`). The cell reads `submission.csv`, turns each finding into percentile ranks, applies the correction to every finding except effusion and synovitis, and writes the file back; if anything fails it keeps the original file. The weights `W` in the cell are those of `rank_tools.cooccurrence_weights` on the 4,349 non-gold studies, rounded to three decimals; a unit test checks that they agree. The public notebook and its checkpoints are not part of this repository. Some of its models were trained by their authors with knees from the Osteoarthritis Initiative; we did not access OAI data.
